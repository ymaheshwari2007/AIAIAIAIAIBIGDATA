Medium level

The nine concrete steps behind those six phases.

1SourcesGHSA live

Advisory feeds

GitHub Security Advisories over the REST API — paginated via the Link header, 5,000 req/hr with a token.

GHSA done · OSV (partner) + NVD enrichment come later.

2Ingestdone

Airflow DAG

A daily thin DAG fetches new advisories using a watermark (only what changed), with retries. Fetch → land.

ingest_ghsa · @daily · incremental

3Store · rawdone

MinIO landing zone

Untouched JSON, immutable and append-only — the raw source of truth we can always re-derive from.

github/dt=<date>/run=<time>/advisories_p<n>.json

4Loaddone

Transform + upsert

Map each raw record to rows, then upsert into Postgres. Idempotent on the identity pair — re-runs never duplicate.

record_to_rows → on_conflict_do_update on (source, source_id)

5Store · curateddone

Postgres schema

Two tables: advisories, and the affected packages hanging off each (one row per package × version range).

advisories 33,874 · affected 62,857 · indexed by (ecosystem, package)

6Index · embed✓ just done

Embed → pgvector

Turn each advisory's summary + description into a 1,024-dim vector. Incremental — only new or changed rows re-embed.

Qwen3-Embedding-0.6B (local, on GPU) · marker: updated_at > embedded_at

7Index · querynext ◀

Retrieval

Given a package or a question: filter affected to the relevant advisories, then rank them by vector cosine distance. Add an HNSW index for speed.

The "R" in RAG — this becomes the agent's input.

8ReasonStage 4

LLM agent

Reads a project's dependencies + the retrieved advisories, reasons about real impact ("are we actually affected?"), and writes findings.

Retrieval feeds it · reasoning model would be Claude

Grafana + Prometheus

Dashboards over both the pipeline's health and the security posture over time — one screen that shows the whole system alive.
